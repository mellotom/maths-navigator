channels 1 + 4

mx_01 · the function generators
[ signal in ]
slews whatever you patch · lag, portamento, a gate = rise / sustain / fall · ±10 v · also feeds the bus
[ trig ]
fires a 0 → 10 v rise then fall, no sustain · retriggers only while falling
[ cycle ]
loops it: an lfo · LED shows on · [ cycle in ] gate high (2.5 v+) does the same
[ rise ] [ fall ]
cw = slower · together they set the period
[ vari-response ]
log ‹ linear (the tick) › expo › hyper-expo (fig.01)
[ unity out ]
straight from the core, not on the bus · 0–8 v cycling · LED ● + ● −
02

control inputs

mx_02 · ±8 v
[ rise cv ] [ fall cv ]
linear · + = longer, − = shorter, around the knob
[ both cv ]
exponential, and backwards: + = faster, − = slower, the whole function
need more range?
add an offset from ch 2 or 3 into the cv jack
need attenuation?
run the cv through ch 2 or 3 first

mx_03 · 0 or 10 v
[ eor ] ch 1
goes high at the end of the rise · low at rest · pulse delay, clock division
[ eoc ] ch 4
goes high at the end of the fall · high at rest, LED on when idle
chain them
eor / eoc into the other channel’s trig, signal or cycle input (fig.04)

09

utilities

mx_09 · maths as a computer
clock divider
clock into [ trig ] · longer rise ignores more clocks
fall = width · too wide and it stays high
envelope / peak follower
audio into [ signal in ] · rise noon (or 3:00 for peaks) · fall sets the response
or out for a positive follower
rectify
half wave: any input › [ or ] · full wave: same signal into 2 and 3, 2 cw, 3 ccw › [ or ]
voltage mirror
cv into 2, knob full ccw · 3 empty, knob full cw › [ sum ]
gate extractor
signal into 2 · 3 negative = threshold · [ sum ] › ch 1 in, rise + fall 0 › [ eor ]
rise = how long above threshold · fall = gate length
logic inverter
gate into ch 4 [ signal in ] › [ eoc ]
flip-flop
set › ch 1 trig · reset › ch 1 both · rise ccw, fall cw, linear › [ eoc ]
forgets after about 3 minutes
